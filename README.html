EcoDorm AI · Build guide

A beginner-readable full-stack hackathon project. Uses PostgreSQL for persistent hostel records. This implementation does not claim to use AWS services.

Architecture

public/index.html, style.css and app.js provide seven interactive views. api/data.js reads saved records. api/analyze-hostel.js validates daily inputs, requests model analysis and saves validated results. api/simulate.js calculates scenarios without storing them. api/ai.js optionally calls a connected LLM and stores validated JSON explanations. lib/eco.js is the shared scoring and cost engine.

Database

hostel_records stores daily inputs and timestamps. hostel_insights stores JSON explanations linked to a record. migrations/0001_init.sql creates tables; seed.sql adds 30 days of synthetic data for blocks A–D.

API contract

GET /api/data?hostel=Block%20A → records, blocks, hostels, selected, insights, assumptions.
POST /api/analyze → hostel, students, water, electricity, waste, temperature, ac, fan, lighting; returns record and insights.
POST /api/simulate → id, ac, water, led, occupancy; returns costs, savings and score improvement.
POST /api/analyze-hostel → daily hostel inputs; returns validated structured AI analysis.
POST /api/ai → id; returns validated structured AI analysis or a clear JSON error.

Demo and deployment

Charts and demo scores are computed from synthetic records. Live AI requires a configured model connection. Contact your EcoDorm administrator if analysis is unavailable. The demonstration uses public read and analyze endpoints so visitors can try the main flow; avoid real personal or sensitive data. Production multi-hostel use should add user authentication and row ownership. Access and public sharing are controlled by the project administrator.

AWS hackathon extension

AWS services are not connected to the current application. A future AWS version could map PostgreSQL to RDS, the model adapter to Bedrock, daily device ingestion to IoT Core, and the API layer to Lambda/API Gateway. Check the hackathon’s eligibility requirements before describing it as an AWS implementation.
